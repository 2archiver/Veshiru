# 2.1 investigation — November 20, 2026

## Donkey Kong Bananza 3.2.0

Both supplied DKB sessions on dfea788 (one on a different PC) end in the guest SDK's
`QueryMountAddOnContentCacheSize`: prepare index 1, request data ID 1, FS fails,
`nn::diag::detail::Abort`. This is a guest panic, not a host allocator or GPU crash.
The container reports one add-on but the old logs don't show its ID or the returned base.
The *source* of a possible zero is reproducible: `BuildNacp` constructs control data from
manifest fields and in 2.0 never initializes the DLC base. At this exact revision
`GetAddOnContentBaseId` only falls back on a missing control object, not a zero field.
`ReadAddOnRomFS` deliberately requires the full ID, matching application family and enabled
DLC; installed data still wins. No index-only lookup, fake RomFS or suppression of a panic.

The `RawNACP` declaration has the same layout in all four reference snapshots below
(the two Lichii headers are identical to 2.0; the other diffs are attribution only).
Both compressed and plain language tables occupy the first 0x3000 bytes. Compile-time checks
cover the DLC field at 0x3070 and total size 0x4000. This is not verification of the user's
original NACP bytes. Boot with the same NUP and DLC enabled. Send `GetAddOnContentBaseId`,
`ListAddOnContent`, `PrepareAddOnContent`, and `OpenDataStorageByDataId` lines and whether
the menu appears. For index 1 we expect base `040074A01BF13000`, requested/carried
`040074A01BF13001`. If the request is still 1 despite a correct service reply, trace the
guest-facing control-data path; don't make FS treat every request for 1 as DLC.

## Mario Kart World 1.8.0

Metabox i7-10750H / GTX 1650: `veshiru_log.txt.old.txt` reports 3.04 GiB available VRAM,
70 windows of 600 presents, mean of their interval averages **53.58 ms** (entire session,
not a race benchmark). At 1057.7 s one window averaged 82.32 ms with 52 intervals over
100 ms, but mean present-fence wait and vblank pacing both rounded to 0 μs. This doesn't
mean GPU execution was free. 213 `BindTiles` out-of-device-memory warnings; on failure the
function rolls back newly allocated blocks, leaving subsequent uploads to retry. 32 image
budget warnings (capped logger). Reported readback windows total 101,960 reads, 77,497
already in flight. Not enough data to rank CPU threads, time GPU passes or calculate a 1% low.

Only sparse allocation recovery changed: after both device-local allocation paths fail due
to device OOM, try an allowed non-local type within VMA's budget. No new passes or waits.
Driver memory-type restrictions may leave no eligible type; non-local access can be slower.
No thread tuning, expanded shader cache, synthetic PGO data or readback synchronization changes.

**UNVERIFIED - needs runtime test:** repeat the same time trial/ghost, camera, lap, resolution,
settings and warm-cache state on 2.0 and 2.1 with frame generation off. Record native present
intervals (not generated frames), average and slowest 1% mean interval per lap; compare
`BindTiles` failures, `CPU readback summary` and `last 600 presents`. For attribution use
`EDEN_NX2_GPU_PROFILE=1`, `EDEN_NX2_GUEST_THREAD_STATS=1` and `EDEN_DKB_FRAME_TRACE=1`
in a separate short run. Record clocks/temperatures, not just settings. Check track texture
residency, then boot Mario Kart 8 and another previously working title on the same build.

## Reference review

Compared the NACP, AOC service, NUP loader, nx2 graphics service, Vulkan allocator/pipeline
cache/scheduler, Dynarmic ARM64 and build/workflow trees against dfea788. Each `LICENSE.txt`
contains GPLv3; file-specific SPDX notices still apply. No third-party code was copied.

| Reference | Snapshot / relevant file | Decision |
|---|---|---|
| MythosOfs/Orchid | `386582a7d4`, `addon_content_manager.cpp`, `nup.cpp` | Adopts zero-aware metadata resolution and can use authentic control data. Adapted the zero check, not its loader or global registration. |
| tasarren/Lichii | build-4 `cc05cad697`, `addon_content_manager.cpp`, `vk_pipeline_cache.cpp` | Adapts the base to the caller's DLC when metadata is zero. Ported that idea to our per-loader carried IDs. Build-4 cache/prebuild and JIT changes aren't profiled fixes for this race; no DLSS port. |
| zortos293/Lichii | `5bcff5fb4b`, `GetAddOnContentBaseId` | Same missing-or-zero guard and caller-aware fallback. No duplicate port or replacement PGO data. |
| Eglantine-Community/Eglantine | nx2 `041b09b1e2`, AOC service; [PR 877](https://github.com/Eglantine-Community/Eglantine/pull/877) | nx2 itself still returns zero for a present zero field; the PR checks non-zero metadata and falls back. Used the defensive rule, retained Veshiru's lazy RomFS and DLC disable key (3168bd33c9). |
