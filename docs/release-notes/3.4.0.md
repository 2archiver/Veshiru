**3.4.0 is the performance release. Switch 2 games spend much less time waiting inside the emulator,
the Wii Remote and Joy-Con 2 mouse from 3.3.0 behave the way they should, and a new Performance page
shows the switches Veshiru uses for your graphics card — and lets you change them — in one place.**

### Performance

- **The two GPU threads spend much less time waiting for each other.** Since 3.3.0 Veshiru parses a
  game's command stream on one thread and runs the draws on a second, but the first one still had
  to stop at every memory read and let the second catch up. A read now waits only for the queued
  work that can change the memory it reads, and the second thread keeps submitting recorded draws
  while it waits. Games that read back their own rendering, such as the ones that put a frame's
  result into a texture, stall less between frames. Heavy scenes that dropped frames while the
  emulator caught up should keep their pace better. `EDEN_NX2_SPLIT=0` puts everything back on one
  thread if you want to compare or something looks wrong.
- **The first thread waits only for the command it depends on.** When a game's command stream reads
  memory, Veshiru now waits for the queued work that can actually change that memory instead of
  everything in front of it, and it keeps submitting recorded draws while it waits. Games that read
  back their own rendering stall less between frames.
- **A Performance page for the switches.** *Configure > Performance* recommends the launch switches
  for NVIDIA, AMD, Intel and macOS hardware, ticks the ones that suit the GPU and driver it finds,
  and marks the ones that do not apply or that the environment already sets. They are saved to
  `nx2_switches.txt` in your Veshiru folder, so they survive updates. *Select Recommended* picks the
  safe set for your machine; the page also holds the shader cache and memory options that used to be
  buried in Graphics. **Per-game tweaks** appear on the same window's *Tweaks* page for the games
  with a known-good preset: tick what you want and *Apply Selected* puts it in the normal tabs.
- **Smaller things that add up.** On a Ryzen X3D processor the guest threads are put on the 3D
  V-Cache cores. Uniform reads compare only the words a draw binds instead of the whole bank,
  repeated image allocations are reused instead of freed and re-created, a fast pipeline lookup sits
  in front of the slow one, and misaligned 64- and 128-bit storage reads in shaders are split
  instead of being viewed as vectors some drivers get wrong.

### Controllers

- **Nunchuk fixes.** The Wii Remote driver no longer reads another extension's bytes (a Classic
  Controller, Motion Plus and so on) as Nunchuk stick and C/Z input, and a connected Nunchuk keeps
  its last stick position when a report does not carry it. A released remote now stops moving: its
  accelerometer and pointer input is cleared instead of staying at the last sample.
- **Joy-Con 2 mouse motion is consistent.** Sensitivity is applied once, so the mouse report and
  the optional right-stick and gyro fallbacks all move by the same amount instead of the stick
  trailing the report.

### Artwork and branding

- **The Veshiru icon is right at every size.** The application icon is rebuilt from the current
  artwork for every size Windows asks for, including the intermediate steps used at 125 % and 150 %
  display scaling, and the About window shows the Veshiru icon rather than looking for the old one.
- **Game artwork keeps the 3.3.0 order.** A bundled icon in `dist/game_icons` still wins, then the
  game's own icon, then bundled box art, then a downloaded cover.

### Good to know

- The Performance page writes `nx2_switches.txt`; a variable you set in the real environment always
  wins over the file, so a launcher or a shortcut can still override one run.
- `EDEN_NX2_PERF=0` turns every renderer optimisation off, and `EDEN_NX2_PERF_SAFE=1` keeps only the
  experimental ones off, if you need to bisect a problem.
- `EDEN_NX2_TC_BUDGET=1` (off by default, for testing) lets the texture cache hold on to more of the
  video memory budget on cards with more than 8 GB, for games that recreate render targets
  constantly.
- Veshiru is a Windows emulator: these notes describe the Windows package, which is the one that is
  built and published.
