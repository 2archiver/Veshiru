**3.4.0 puts the emulator's switches where you can see them: a Performance page that recommends and
saves the launch switches for your graphics card, and a frame generation page of its own. The Wii
Remote Nunchuk and the Joy-Con 2 mouse behave the way they should, Ryzen X3D machines get the right
cores, and the application icon is rebuilt.**

### Settings

- **A Performance page.** *Configure > Performance* lists the launch switches Veshiru uses for the
  renderer as checkboxes, one group per vendor (NVIDIA, AMD, Intel, macOS), and shows what the
  graphics card and driver it found make of each one: *Recommended*, *Optional*, *Unsupported*, or
  *Set by environment* when a variable is already set for you. *Select Recommended* ticks the set
  that suits this machine. Ticked switches are written to a marked block of `nx2_switches.txt` in
  your Veshiru folder (`%APPDATA%\veshiru`, a portable `user\` folder, or the copy next to
  `veshiru.exe`), which is read at startup, so they survive updates and a launcher can still
  override one run. The shader cache and memory options moved to the same page.
- **Frame generation has its own page.** The Frame Generation settings leave the Graphics tab for
  *Configure > Frame Generation*, so the scaling, generation and presentation options sit together
  instead of being spread over Graphics and Advanced.
### CPU

- **Ryzen X3D parts are laid out from their caches.** `prefer_3d_vcache` (CPU page, on) puts the
  guest threads and the GPU back thread on the 3D V-Cache cores and background work on the other
  core complex when a processor has two L3 domains of different sizes, instead of pinning from the
  core list alone. `EDEN_NX2_CPU_LAYOUT=2` also gives the split GPU front a core of its own; a
  machine without two domains keeps the old plan.

### Controllers

- **Nunchuk fixes.** The Wii Remote driver only reads extension bytes as Nunchuk data when the
  remote has identified a Nunchuk, so a Classic Controller or Motion Plus is no longer read as a
  stick pulled to one side with C and Z held. While a Nunchuk is connected, a report that does not
  carry extension bytes keeps the last stick and button state instead of zeroing it.
- **A released remote stops moving.** Releasing a Wii Remote clears its motion and pointer input and
  forgets the last sample, so the emulated pointer does not stay at the edge of the screen or keep
  reporting acceleration.
- **Joy-Con 2 mouse motion is consistent.** Sensitivity is applied once, so the mouse report and the
  optional right-stick and gyro fallbacks all move by the same amount instead of the stick trailing
  the pointer.

### Artwork

- **The Veshiru icon is right at every size.** The application icon is rebuilt from the current
  artwork for every size Windows asks for, including the intermediate steps used at 125 % and 150 %
  display scaling, and the About window shows the Veshiru icon instead of looking for the old one.

### Good to know

- The Performance page writes `nx2_switches.txt`; a variable you set in the real environment always
  wins over the file, so a shortcut or a launcher can still override one run. The switches are read
  at startup, so changing one needs a restart.
- Per-game presets still decide a game's recommended settings; what you set per title is
  unchanged.
