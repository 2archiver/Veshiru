**3.2.0 is a general performance and polish release: the game library's Versioned List becomes the
cover-row Carousel View, game-time freezes from the all-zero memory trim are cut into slices, the
split GPU thread gets dedicated cores on 4-core-performance laptops, and a hot-path diagnostic
leaves the render loop. No rendering path changed, so looks are exactly as in 3.1.**

### Game library

- **Carousel View replaces Versioned List.** View > Game List Mode now offers Tree View, Grid View
  and Carousel View. The carousel is a single cover row across the window: scroll it with the
  wheel, drag it, or move with the arrow keys, and the search bar filters it. If you used the
  Versioned List, your profile lands on the carousel automatically.
- Artwork, badges, favourites, launching, the context menu and per-game settings are unchanged.

### What's smoother

- **The memory trim no longer freezes a running game.** Veshiru occasionally releases all-zero
  guest pages from the CPU working set. On a 24 GB laptop a single pass over a running game took
  5.7 seconds and cost frames of up to 2.6 seconds (Yoshi and the Mysterious Book, the report
  behind this release). While a game is presenting, the pass now runs in 512 MiB slices that cost
  a fraction of a frame each and stop the moment you pause; loading screens and idle time still
  get the full pass, so the memory saving arrives just the same.
- **Dedicated GPU thread cores on more laptops.** The two split GPU threads now get a performance
  core each on CPUs with four performance cores (i5-12450H and similar), instead of being left
  unpinned and shared with the emulated CPU threads. Six or more performance cores still pins the
  emulated cores too.
- **Less per-frame bookkeeping.** The native compute storage-binding counters ran on every binding
  (hundreds of thousands per 10 seconds in Yoshi) and now wait for `EDEN_NX2_BINDING_STATS=1`.

### Good to know

- Frame generation is untouched and still costs native FPS on some systems; leave it off when you
  want the real frame rate.
- The release notes above describe changes, not measured gains: the frame-rate comparison against
  3.1.0 and against Satsuma requires a run on the reference GTX 1650 machine, and
  `docs/performance/3.2-log-review.md` records exactly what the supplied logs do and do not show.
